# Fluid Paint — матеріали для #buildinpublic

Зріз станом на 2026-09-09. Це редакційний банк, а не твердження про реліз у
продакшені. Перед публікацією слід перевірити поточний deploy і зняти свіжі
візуали на тій самій версії коду.

## Наратив продукту

Fluid Paint перетворюється зі старого WebGL-демо на рушій рідкої фарби, який
працює на desktop і mobile, має публічний Stroke API та може перемальовувати
векторні історії Tilecraft живими мазками. Головна цінність — не просто ефект
фарби, а контрольована симуляція: щетинки, тиск, змішування пігментів, повторне
відтворення та перевірювана поведінка на двох WebGL-шляхах.

Найсильніша серія для соцмереж: «як ми перетворюємо красивий експеримент на
надійний продуктовий рушій». У ній природно поєднуються видимі демо, мобільні
баги, API-дизайн, колір і тестування.

## Пріоритетні теми

### 1. Векторна історія стає живим малюнком

Гачок: «Ми під'єднали JSON із векторними штрихами до симуляції рідкої фарби —
і замість миттєвого імпорту малюнок народжується мазок за мазком».

Що показати: 10–15 секунд playback fixture на 1× і 8×, бажано split-screen.
Підкреслити, що 8× не викидає точки. Джерела:
`docs/TILECRAFT-STORY-PLAYBACK.md`, `docs/api-usecases.md`.

### 2. Баг, який жив у двох пікселях слова `LINEAR`

Гачок: «На одному Android усі щетинки пензля зліталися в нижній лівий кут.
GPU підтримував потрібні фічі — але повертав нулі через texture completeness».

Що показати: existing bug screenshot
`docs/bug-reports/non-random-wristles-brush-hits.png`, поруч виправлений мазок.
Технічний якір: state textures мають бути `NEAREST`.

### 3. Біле полотно на iPhone, хоча capability check був зелений

Гачок: «iPhone казав, що підтримує float render targets. Але реальний blend у
них не працював — і користувач бачив здоровий UI з абсолютно білим canvas».

Що показати: до/після на iPhone 14 та маленьку схему probe → float/half-float.
Урок: перевіряти конкретну GPU-операцію, а не назву extension.

### 4. Навіщо рушію другий host

Гачок: «Чотири фази рефакторингу не побачили баг. Порожня сторінка з canvas і
трьома controls знайшла його одразу».

Що показати: main app поруч з `examples/minimal`. Розповісти про app-owned
global, який кидав `ReferenceError` до першого splat.

### 5. Жовтий + синій мають давати зелений

Гачок: «Звичайний color picker говорить RGB. Наш пензель думає пігментами RYB.
Якщо просто з'єднати їх, UI показує один колір, а мазок кладе інший».

Що показати: picker swatch, brush preview і мазок одного кольору; потім
yellow-over-blue. Технічний якір: перетворення на межі системи.

### 6. Тесту не можна довіряти, поки він не зловив поломку

Гачок: «Ми навмисно зламали і колір, і крок симуляції. Golden tests упіймали
обидві поломки й навіть показали, в якому шарі сталася зміна».

Що показати: таблицю `paintHash/screenHash`, а не стіну terminal output.

### 7. Чому mobile panel плаває над полотном

Гачок: «Ми вже зібрали акуратну sidebar. Потім протестували на телефонах і
викинули її: 300 px забирали третину місця для малювання».

Що показати: docked prototype проти floating/collapsed bar. Це хороший пост про
рішення після робочого прототипу, а не після макета.

### 8. Один API для живого вводу й детермінованого replay

Гачок: «Миша живе за wall clock. Записаний штрих живе за model clock. Ми дали
обом один Stroke API, але не дозволили їхньому часу змішуватися».

Що показати: коротку timeline-схему `begin → strokeTo + advance(1/60) → end`.

### 9. Рефакторинг, який доводить, що нічого не змінив

Гачок: «Винести renderer легко. Довести, що фарба лишилась тією самою, складніше».

Що показати: однакові кадри WebGL 1/2 і 12 paint hashes. Згадати чесну межу:
goldens не бачать жести та реальну GPU-продуктивність.

### 10. Продуктова механіка зі старого демо

Гачок: «Наша найбільша зміна не новий shader. Це межа: UI керує рушієм лише
через публічні команди, а сам рушій більше не знає про панель і picker».

Що показати: проста схема `Host UI → FluidEngine → Brush/Simulation/Renderer`.

## Готові чернетки

### Пост 1 — універсальний короткий

Сьогодні Fluid Paint навчився не просто імпортувати векторний малюнок, а
перемальовувати його живими мазками.

Tilecraft JSON проходить через публічний Stroke API: колір, товщина, тиск і всі
точки кривої доходять до симуляції рідкої фарби. На 8× ми не проріджуємо шлях —
виконуємо 8 повних модельних кроків за показаний кадр.

Наступний крок — нормальні Play/Pause/Restart і чесні model ticks/s у UI.

Що цікавіше побачити наступним: процес малювання чи різницю RGB та RYB кольорів?

#buildinpublic #webgl #creativecoding

### Пост 2 — X

На Android усі щетинки Fluid Paint зліталися в нижній лівий кут. GPU мав усі
потрібні фічі; проблема була в `LINEAR` filtering для state texture: shader
отримував нулі. Замінили на `NEAREST`, відтворили баг на desktop і закрили його
на реальному девайсі. #buildinpublic #webgl

### Пост 3 — LinkedIn

Чотири фази рефакторингу Fluid Paint проходили тести. А потім ми створили другий
host: порожня сторінка, canvas і три controls. Малювання не працювало взагалі.

Причина виявилася майже комічною: код пензля читав debug-змінну, яку оголошував
тільки головний `index.html`. У знайомому середовищі все було добре. У будь-якому
іншому host виникав `ReferenceError` ще до нанесення фарби.

Мінімальний host також показав, що enum моделі кольору й список shaders належали
app, хоча були частиною контракту рушія. Ми перенесли їх у публічний API й
закріпили перевіркою 18/18.

Для нас це став найкращий тест межі модулів: якщо «повторно використовуваний»
рушій не може запустити друга маленька програма, межа ще не справжня.

#buildinpublic #javascript #webgl #softwarearchitecture

### Пост 4 — Threads

Маленький урок із Fluid Paint: зелений capability check ще не означає, що GPU
реально виконає потрібну операцію.

На iPhone 14 float render target створювався успішно, але blending давав біле
полотно. Ми додали runtime-пробу саме того blend, який використовує пензель:
працює float — лишаємо float; ні — переходимо на half-float.

Фікс підтвердили на фізичному iPhone 14. Тепер capability — це виміряна
поведінка, а не обіцянка API.

#buildinpublic #webgl #ios

### Пост 5 — про колір

Color picker показував правильний колір. Brush preview теж виглядав нормально.
Але фарба на полотні могла бути іншою.

Причина: picker працює в RGB, а Fluid Paint змішує пігменти в RYB. Значення
виглядали схожими, тому помилка була правдоподібною й тихою.

Ми описали один колірний контракт для picker, preview і shader, а потім
перевірили всю межу чисельно — 42/42. Найважливіше: raw paint hashes лишилися
стабільними, тобто виправили відображення, не змінивши саму симуляцію.

#buildinpublic #creativecoding #colortheory #webgl

### Пост 6 — про тести

«Усі golden tests зелені» звучить добре. Але чи впадуть вони від справжньої
поломки?

Для Fluid Paint ми навмисно зробили дві диверсії:

- вимкнули RYB rendering — змінився тільки screen hash;
- змінили крок симуляції з 1/60 на 1/61 — змінилися і paint, і screen hashes.

Так ми перевірили не лише результат тесту, а його чутливість. І залишили чесну
межу: headless SwiftShader не доводить швидкодію чи жести на фізичному GPU.

#buildinpublic #testing #webgl

## Серія на 7 публікацій

1. Візуальний тизер: Tilecraft → Fluid Paint playback.
2. Як публічний Stroke API зробив цей playback можливим.
3. RGB picker проти RYB pigment mixing.
4. Android-баг із щетинками в нижньому лівому куті.
5. Біле полотно на iPhone та runtime capability probes.
6. Другий host як тест справжньої модульності.
7. Golden tests, sabotage і межі автоматичної перевірки.

Публікувати краще від найбільш видимого результату до технічної глибини. Кожен
наступний пост може посилатися на попередній як на частину перетворення демо на
рушій.

## Перед публікацією перевірити

- Чи задеплоєні commits `d96d81e` і `b1b18d8`; якщо ні, писати «у dev build»,
  а не «в продукті».
- Повторити `npm run test:tilecraft`, `npm run test:tilecraft:gpu`,
  `npm run test:color` і `npm run build` на версії, яку показує відео.
- Не називати `storySpeed=8` восьмикратним скороченням реального часу без
  виміряних model ticks/s і FPS.
- Не узагальнювати результат одного iPhone 14 на всі iPhone.
- Не показувати локальні абсолютні шляхи, console tokens або приватні story
  fixtures у скриншотах.

## Наступні пости, які можна заробити розробкою

- UI playback із Play/Pause/Restart, progress і виміряними model ticks/s/FPS.
- Порівняння одного Tilecraft frame з collage усіх чотирьох frames.
- Профілі Faithful/Balanced/Fast із чітким описом, де втрачається якість.
- Реальні заміри playback на Galaxy Tab S9, Samsung A56 та iPhone 14.
- Публічний мінімальний приклад інтеграції Stroke API з 20–30 рядками коду.
